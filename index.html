Outlook signatures that set themselves

An event-based Office.js add-in that drops a remotely managed HTML signature into every new email. There is no task pane and no button to press. You open a compose window and the signature is already there.

View on GitHub Deploy guide

How it works

  1. A user opens a new compose window in Outlook.
  2. Outlook fires the OnNewMessageCompose event.
  3. commands.js fetches signature.html from your static host.
  4. The signature is inserted with setSignatureAsync(), falling back to body.setAsync() on older builds.

Because the signature is fetched on each compose, you can change it by editing one file and pushing. You don't need to change the manifest or sideload the add-in again.

Where it runs

Windows

New Outlook for Windows, and classic Outlook on Windows 10 version 1903 or later.

Mac

New Outlook for Mac only. Classic Outlook for Mac doesn't support event-based activation.

Web

Outlook on the web, signed in with a Microsoft 365 account.

Classic Outlook for Windows builds older than Version 2403 can't run the async/await code in commands.js, so the signature won't appear there. The README explains the workaround.

What's in the repo

manifest.xmlThe add-in manifest. You sideload it into Outlook.
commands.jsThe event handler that fetches and inserts the signature.
signature.htmlThe HTML signature fragment. Edit this to change everyone's signature.
_headersCORS headers so Outlook can fetch the files.
skills/Notes for extending the POC: per-user signatures, templating and caching.

Get started

  1. Fork or clone the repository.
  2. Edit signature.html with your name, title, contact details and logo.
  3. Deploy the repo as a static site. The guide uses Cloudflare Pages on the free plan.
  4. Replace the YOUR_DOMAIN placeholders in manifest.xml and commands.js, and give the manifest a fresh GUID.
  5. In Outlook, go to Insert → Add-ins → My Add-ins → Add a Custom Add-in → Add from File and pick your manifest.xml.

The full deploy guide and troubleshooting notes are in the README.

Is DIY right for you?

This is the DIY end of the spectrum: one signature for everyone, nothing to run, and it's yours once you fork it. If you need per-user signatures, an admin dashboard or central deployment, have a look at a commercial platform such as SigHQ to see what that space looks like.
